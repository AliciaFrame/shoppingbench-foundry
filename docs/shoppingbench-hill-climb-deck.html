Frontier tuning

Tune the whole agent system—then the model.

Frontier tuning is an evaluation-led path to higher agent performance: define what good means, measure the starting point, improve the agent surface, and change model weights only when a residual policy gap remains.

01 / DEFINE

Define the evals

Translate the user outcome into measurable correctness, process, grounding, safety, cost, and latency gates.

02 / MEASURE

Score the baseline

Run a fixed development set, preserve every trace, and identify where the current agent fails before changing anything.

03 / OPTIMIZE

Optimize the agent

Improve prompts, skills, tool definitions, schemas, and orchestration first—the fastest and least expensive levers.

04 / ADAPT

Fine-tune if needed

Fine-tune only when calibrated evidence shows a learnable policy failure that agent configuration cannot clear.

Operating principleUse the cheapest effective lever. Escalate only with evidence.

Experiment design

Every climb had a gate.

1. Baseline

Freeze data, tools, model, and canonical grader.

2. Optimize

Generate candidates on disjoint optimization cases.

3. Gate

Reject candidates that do not improve deterministic development metrics.

4. Train selectively

Use RFT only when base failure is 25-50% and a calibrated reward exists.

What we learned

Five operating principles for agent improvement.

1. Deterministic gates beat vibes

LLM judges nominate. Task-specific invariants decide.

2. Calibrate before training

RFT needs a measurable 25-50% base failure regime.

3. Reward design is product design

Small weights can reshape tool behavior and create unintended strategies.

4. Evaluate checkpoints, not just finals

The final Web artifact erased almost all of the Step 10 gain.

5. Preserve lineage

Datasets, graders, configs, receipts, and raw holdouts make the story reproducible.

6. Know when to stop

Without new hard cases, another Web run would recycle evidence rather than create it.
